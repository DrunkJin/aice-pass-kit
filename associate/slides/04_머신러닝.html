PART 1

분류냐, 회귀냐

모델을 고르기 전에 딱 하나만 보면 돼요. 맞혀야 하는 값(타깃, y)이 어떻게 생겼는가.

y 를 먼저 보세요!

타깃(y)을 보면 바로 결정돼요

CLASSIFICATION

분류: "어느 쪽이야?"

정답이 정해진 몇 개의 범주 중 하나예요.

Churn: Yes / No → 이진분류
Survived: 0 / 1 → 이진분류
grade: low / mid / high → 다중분류

모델 이름에 Classifier가 붙어요. 평가는 accuracy, f1 등으로 해요.

REGRESSION

회귀: "얼마야?"

정답이 연속적인 숫자예요. 소수점도 의미가 있어요.

Time_Driving: 17.5분
price: 3억 2천만 원
Delivery_Time: 42.0분

모델 이름에 Regressor가 붙어요. 평가는 MAE, MSE, R² 등으로 해요.

숫자라고 다 회귀는 아니에요 Pclass(1·2·3등석)나 grade(0·1·2)는 숫자지만 범주예요. 2.5등석은 없잖아요? "중간값이 의미가 있나?"를 물어보면 구분돼요.
타깃 quality가 3~9 정수이고 "품질 등급을 분류하라"고 해요. 분류? 회귀?
분류(다중분류)예요. 문제가 "분류"라고 했고, 값이 몇 개의 등급으로 정해져 있어요. 문제의 지시가 항상 우선이에요.
타깃 TotalCharges(누적 요금, 예: 1889.5)를 예측해요. 분류? 회귀?
회귀예요. 소수점까지 의미가 있는 연속값이니 ...Regressor를 쓰고 MAE/RMSE로 평가해요.

하이퍼파라미터: 학습 전에 정하는 "설정값"

모델이 스스로 배우는 값이 아니라, 우리가 미리 정해 주는 규칙이에요. 시험에서는 문제가 값을 알려주니 그대로 옮겨 적기만 하면 돼요.

이름뜻비유 · 효과
max_depth트리가 내려갈 수 있는 최대 깊이(질문 횟수)스무고개 횟수 제한. 크면 외우고(과적합), 작으면 대충 배워요(과소적합).
n_estimators만들 나무(모델)의 개수투표하는 심사위원 수. 많을수록 안정적이지만 느려져요.
min_samples_split노드를 나누려면 필요한 최소 샘플 수"최소 몇 명은 있어야 반을 나눈다". 크면 덜 쪼개요(과적합 방지).
random_state난수 시드주사위 순서를 고정하는 것. 같은 값이면 매번 같은 결과가 나와요.
learning_rate부스팅에서 한 번에 고치는 정도보폭. 너무 크면 지나치고, 너무 작으면 오래 걸려요.
random_state를 빼먹지 마세요빠지면 실행할 때마다 점수가 달라져서, 채점 기준 값과 맞지 않을 수 있어요.

PART 3

모델 채점하기: 평가지표

"정확도 97%"는 좋은 걸까요? 무엇을 맞히고 무엇을 틀렸는지 나눠 봐야 알 수 있어요. 분류와 회귀는 지표가 완전히 달라요.

혼동행렬: 맞힌 것과 틀린 것을 4칸으로

예측 0 (음성)
예측 1 (양성)
실제 0
TN맞게 "아님"
FP괜히 "맞다"
거짓 경보
실제 1
FN놓친 "맞음"
놓친 환자
TP맞게 "맞다"

T/F = 맞혔나 틀렸나 · P/N = 예측을 무엇으로 했나

confusion_matrix() 출력도 이 배치 그대로예요.
[[TN, FP], [FN, TP]]

정확도 accuracy
(TP + TN) / 전체
전체 중 맞힌 비율
정밀도 precision
TP / (TP + FP)
"양성"이라고 한 것 중 진짜 양성 비율
재현율 recall
TP / (TP + FN)
진짜 양성 중 찾아낸 비율
F1 score
2 × P × R / (P + R)
정밀도와 재현율의 조화평균

언제 어떤 지표를 볼까?

놓치면 큰일

재현율 recall

암 진단, 이상거래 탐지, 이탈 고객 찾기처럼 놓치는 게(FN) 치명적일 때 봐요. "의심되면 일단 잡아라."

헛방이 비쌈

정밀도 precision

스팸 필터처럼 멀쩡한 걸 잘못 걸러내는 게(FP) 곤란할 때 봐요. "확실할 때만 말해라."

둘 다 중요

F1 score

데이터가 불균형이거나 정밀도·재현율을 같이 봐야 할 때 써요. 한 숫자로 비교하기 좋아요.

정확도의 함정 고객 100명 중 이탈자가 5명이면, 모델이 무조건 "유지"라고만 답해도 정확도가 95%예요. 그런데 재현율은 0이에요. 참고 저장소의 LGBM 예제가 실제로 이랬어요(정확도 73%, 재현율 0).
혼동행렬이 [[72, 0], [3, 39]]예요(행=실제, 열=예측). 재현율은?
TP=39, FN=3 → 39 / (39+3) = 0.929. 정밀도는 39 / (39+0) = 1.0이에요. 다음 슬라이드의 실제 실행 결과와 같아요.

회귀 지표: 얼마나 빗나갔나

지표뜻좋은 값
MAE오차 절댓값의 평균. "평균 몇 분 틀렸나"작을수록 ↓
MSE오차 제곱의 평균. 큰 실수에 벌점이 커요작을수록 ↓
RMSE√MSE. 단위가 원래 값과 같아져요작을수록 ↓
R²평균으로 찍는 것보다 얼마나 나은가 (최대 1)클수록 ↑
손으로 계산해 보기
정답 [10, 20, 30] 예측 [12, 18, 33]
오차 = [2, -2, 3]
MAE = (2+2+3)/3 = 2.33
MSE = (4+4+9)/3 = 5.67 RMSE = √5.67 = 2.38
RMSE 함수는 따로 없다고 생각하세요버전마다 다르니 np.sqrt(mean_squared_error(...))로 계산하는 게 가장 안전해요.
