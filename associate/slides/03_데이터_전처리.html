shuffle=True기본값. 시계열이면 False
이름은 문제 따라샘플 문항은 X_valid, y_valid라는 이름을 써요. 문제에 적힌 이름 그대로 받으세요.

스케일링: 숫자 범위 맞추기

나이(0~100)와 요금(0~10,000)을 그대로 넣으면 큰 숫자 컬럼이 학습을 좌우해요. 특히 딥러닝·KNN·로지스틱 회귀에 중요해요. (트리 모델은 영향이 거의 없어요)

MinMaxScaler

(x − min) / (max − min)

결과가 0~1 사이. train 범위 밖 값은 1을 넘을 수 있어요.

train [10, 20, 30, 40] → [0, 0.333, 0.667, 1]
test  [25, 50]         → [0.5, 1.333]

StandardScaler

(x − 평균) / 표준편차

결과의 평균 0, 표준편차 1. 이상치에 조금 덜 민감해요.

train [10, 20, 30, 40] → [-1.342, -0.447, 0.447, 1.342]
test  [25, 50]         → [0.0, 2.236]   (평균 25, 표준편차 11.18)
In [19]:
from sklearn.preprocessing import MinMaxScaler   # 또는 StandardScaler
scaler = MinMaxScaler()
X_train = scaler.fit_transform(X_train)   # train: 기준을 배우고(fit) + 변환
X_test = scaler.transform(X_test)         # test: 배운 기준으로 변환만

fit은 train에만: 데이터 누수 막기

✅ 올바른 순서

X_train = scaler.fit_transform(X_train)
X_test = scaler.transform(X_test)

시험지(test)는 시험 날 처음 보는 거예요. 기준(min, max, 평균)은 공부한 자료(train)에서만 정해야 해요.

❌ 누수 (test 정보가 학습에 섞임)

X = scaler.fit_transform(X)      # 분할 전에 fit
X_test = scaler.fit_transform(X_test)  # test에 fit
왜 문제일까?test의 최댓값·평균을 미리 보고 기준을 정하면 검증 점수가 실제보다 좋게 나와요. 실제 서비스에서는 미래 데이터를 미리 볼 수 없어요.
시험 포인트"학습 데이터로 fit한 scaler로 검증 데이터를 변환하라"는 표현이 나오면 위의 ✅ 두 줄이에요. 이름은 보통 scaler예요.
결과는 numpy 배열스케일링 후 X_train은 DataFrame이 아니라 배열이 돼요. .head() 대신 X_train[:5]로 보세요.

전처리 순서 체크리스트

  • Q4잘못된 범주('-') 행 제거
  • Q6이상치 제거 (부등호 방향 확인)
  • Q7결측치: 많은 컬럼 drop → 행 dropna / fillna
  • Q8ID·시간 문자열 등 불필요 컬럼 drop(axis=1)
  • Q9문자열 숫자는 먼저 숫자로 → 나머지 object를 get_dummies
  • Q10X/y 분리 → split(X, X, y, y) → scaler fit은 train만
split 결과를 X_train, y_train, X_valid, y_valid 순서로 받았어요. 무엇이 문제일까요?
반환 순서는 X_train, X_valid, y_train, y_valid예요. 에러 없이 이름만 뒤바뀌어 모델이 엉뚱하게 학습돼요.
스케일링을 train_test_split 전에 전체 X에 하면 안 되는 이유는?
검증 데이터의 정보(min·max·평균)가 기준에 섞이는 데이터 누수예요. 분할 후 train에만 fit하세요.
타깃 비율이 9:1이에요. split에 꼭 넣을 인자는?
stratify=y — 검증 세트에도 9:1 비율이 유지돼요.
